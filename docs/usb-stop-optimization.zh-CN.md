# USB 停止耗时优化记录

日期：2026-09-24。目标是缩短用户点击停止后，直至手机普通 USB 配置确认恢复的等待。
声音停止在协议收尾和 USB 恢复之前发生。此次全部输出静音，未更改驱动。

## 实现

原流程只按 RELS 数量退出；本机 iOS 26.6 已发送有效 SYNC STOP，但没有 RELS，因此仍等待约 6 秒。
新增 `Capture/AudioStopDrainPolicy.h`，允许在以下条件全部成立时提前完成协议收尾：

1. 手机发出的 SYNC STOP 已通过协议解析，并成功写出对应回复。
2. 协议仍处于 Stopped，连续 250 ms 没有媒体尾包。
3. StreamDecoder 中没有尚未拼完的数据包。

迟到媒体会重新开始计算静默窗口。缺少有效 STOP、仍有媒体或未完成数据包时，继续使用原来的
6 秒等待上限；开始收尾前手机已停止的分支保留原 1 秒上限。RELS 齐全仍可立即结束收尾。
快速模式把收尾 read timeout 调整为 50 ms，以观察 250 ms 窗口；正常播放的 USB 读取不变。

关闭流句柄后的自动恢复观察窗口从 3 秒缩短为 1 秒；同时仍要求连续观察到符合条件的
QuickTime 残留状态，才允许启动一次恢复请求。

以下机制保持原逻辑：

- 流句柄先关闭，再从独立辅助程序发出配置切换。
- 精确手机身份/USB 拓扑匹配及驱动状态检查。
- 恢复控制只发一次；父设备缺失期间不打开控制句柄。
- 辅助程序等待对应设备移除/重新出现，保留 750 ms 稳定窗口和 15 秒等待预算。
- 主进程同时检查官方 usbmux 和完整普通 USB PnP 状态，连续两次正常才确认完成。
- 原来的恢复观察窗口和失败提示。

新增 `audio_stop_drain` 和 `audio_stop_timing` 日志，分别记录退出条件、各阶段耗时；
AudioProbe 输出 `stop_ms`，直接测量同步 `ab_stop` 调用耗时，包含停止请求到工作线程响应的时间。
WPF 在异步停止期间继续读取状态，显示音频收尾 / USB 恢复的当前阶段。

## 真机结果

设备为 iPhone 15 Pro Max / iOS 26.6；Windows Realtek WASAPI 输出全程静音。
每轮采集 12 秒（包含连接初始化），随后停止并再次枚举手机。
本轮输入最后一块峰值为 -120 dBFS；有连续 PCM 数据，不据此声称完成有声试听。

| 轮次 | `ab_stop` 耗时 | 音频包 | 视频包/字节 | 欠载/丢帧 | 停止后状态 |
|---|---:|---:|---:|---:|---|
| 原保守时序对照 | 15.710 秒 | 428 | 0 / 0 | 0 / 0 | 普通 USB 已确认，accessible=1 |
| 快速模式 1 | 10.603 秒 | 429 | 0 / 0 | 0 / 0 | 普通 USB 已确认，accessible=1 |
| 快速模式 2 | 10.279 秒 | 443 | 0 / 0 | 0 / 0 | 普通 USB 已确认，accessible=1 |
| 快速模式 3 | 10.176 秒 | 449 | 0 / 0 | 0 / 0 | 普通 USB 已确认，accessible=1 |
| 最终发布包，未设置模式环境变量 | 10.854 秒 | 420 | 0 / 0 | 0 / 0 | 普通 USB 已确认，accessible=1 |

快速模式四轮平均 10.478 秒，比本轮保守对照缩短约 5.23 秒，约 33%。
前三轮协议收尾耗时 0.264–0.316 秒，原对照为 6.211 秒。
剩余大头在 USB 配置切换和 Windows/Apple 驱动恢复；完整停止仍约 10 秒。
不能把删除的等待窗口长度直接当作总耗时的保证降幅。

前三轮后，最终版本进一步要求协议仍处于 Stopped，排除畸形 STOP 或后续重新协商触发提前收尾；
随后完成了表中最终发布包实测。Native 回归和最终 WPF 窗口检查通过。

新增回归覆盖：无 STOP 不提前结束、静默窗口边界、迟到媒体重置窗口、未拼完的数据包、
保守模式原时限、RELS 齐全立即退出、已停止分支、畸形 STOP 被拒绝。
原有禁止重复 USB 恢复请求和连续正常状态确认测试仍通过。

证据保存在 `test-results/2026-09-24-usb-stop/`，其中 `runtime-manifest.json` 为最终发布文件哈希。
本记录仅证明本机短时多轮启停通过，不代表其他 iOS/驱动组合或长期压力测试完成。
没有进行物理拔线、驱动超时故障注入或应用进程强制终止测试。

## 回退到原时序

默认是快速模式。保留进程级环境变量用于兼容性排查，不修改系统环境或驱动：

```powershell
$env:AB_USB_STOP_MODE='conservative'
./dist/iOSAudioBridge/iOSAudioBridge.exe
```

恢复快速模式时，先关闭程序，再运行：

```powershell
Remove-Item Env:AB_USB_STOP_MODE
./dist/iOSAudioBridge/iOSAudioBridge.exe
```

也可显式设置 `AB_USB_STOP_MODE=fast`；其他非空值按保守模式处理。
保守模式恢复原收尾等待逻辑和 3 秒自动恢复观察窗口。
快速模式不在恢复失败后重复切换 USB；无法确认恢复仍会显示重新插拔提示。
