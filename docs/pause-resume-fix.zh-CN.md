# B 站暂停导致监听结束：修复与验证

日期：2026-09-24。设备：iPhone 15 Pro Max / iOS 26.6，手机 B 站，Windows Realtek 输出静音。

## 原因

原协议代码把所有 SYNC STOP 都标为 `Stopped`，AudioSession 随即抛出
`iPhone ended the audio session`，进入正常的句柄关闭和 USB 恢复。
它没有区分“主机要求停止监听”与“手机暂停当前音频”。

用户旧日志中 09:24、09:25、09:26 的三次恢复都走了 `peer_stopped` 对应的 1 秒收尾分支，
最终 `failure=true`。本轮 B 站真机复现直接记录到暂停产生的手机 STOP。
此前“程序不会仅因手机暂停而停止”的回答没有覆盖这个协议分支，需要纠正。

## 修改

- 协议层增加 `Paused`，并单独保存本地主动停止意图。
- 主机仍在监听时收到有效 STOP，只发送协议回复并进入 Paused，不关闭 USB、发送 HPA0 或执行配置恢复。
- 接收到新的 PCM 或手机重新协商时可恢复 Streaming；沿用同一个已打开的 USB 会话。
- 真正调用 stop 后仍走完整释放流程；迟到音频、PING、CWPA 都不能撤销本地主动停止，
  迟到 CWPA 也不再发送 HPA1 重新请求音频。
- 已确认的手机暂停不受初次音频协商超时影响，仍保留 USB 物理存在性与输出线程错误检查。
- WASAPI 在暂停期间保持输出静音。恢复时先累计至正常启动水位，再继续消耗 PCM，避免第一包刚到就被取空。
  默认启动水位为 3072 帧；不新增队列，增益仍平滑进入。
- 已确认暂停/恢复准备期间不计为欠载，恢复完成后的实际短缺仍计数。
- 增加 `audio_source_paused`、`audio_source_resumed` 和明确的会话错误日志。

## 真机 USB 暂停/恢复验证

用户在 180 秒的静音采集期间操作 B 站。日志记录：

| 暂停事件 | 恢复事件 | 暂停时长 | 结果 |
|---|---|---:|---|
| 09:31:42.518，音频包 1080 | 09:31:53.060，音频包 1081 | 10.541 秒 | 同一 USB 会话恢复 |
| 09:32:10.512，音频包 1899 | 09:32:18.865，音频包 1900 | 8.353 秒 | 同一 USB 会话恢复 |
| 09:32:32.990，音频包 2562 | 09:32:36.151，音频包 2563 | 3.161 秒 | 同一 USB 会话恢复 |
| 09:32:50.830，音频包 3251 | 测试结束时仍暂停 | 持续到第 180 秒 | 保持 Ready、output_active=1、source_idle=1 |

整个监听期间仅一次 USB 激活和一次 bulk 接口打开；暂停之间没有恢复/重新激活。
第 180 秒后由测试工具按指定时长主动调用 stop，才执行 USB 恢复，返回码 0，手机重新可访问。
合计音频包 3251、视频包/字节 0/0、丢帧 0，提交 PCM 3,329,024 帧。

**这轮真机测试发生在恢复缓冲准备改动之前，真实记录为欠载 8 次，不能记成零。**
新增恢复缓冲准备就是为处理该结果；协议和 USB 暂停逻辑在后续改动中保持不变。

## 最终恢复缓冲自动验证

最终发布版 `AudioProbe --pause-silence-test 2` 使用真实 Realtek WASAPI 输出和合成静音 PCM：

1. 正常供音，再标记暂停并停止供给；输出必须持续 active，队列排空并保持 idle。
2. 恢复后只送入一个 1024 帧 packet；验证这些帧保留在队列，未立即提交。
3. 按约 21.33 ms 间隔继续供给 1024 帧 packet；水位准备完成后恢复提交。
4. 重复三个周期，并验证计数不因暂停或恢复产生欠载。

结果：三轮 `active=1 resumed=1 underruns=0`，累计提交 404,128 帧，
period=480、endpoint=1056，最终欠载 0。Native 回归和最终 WPF 隐藏窗口检查均通过。

Native 新增测试覆盖手机 STOP 回复、重复暂停、直接恢复 PCM、重新协商恢复、
暂停后的主动停止、迟到音频/PING/CWPA 不重启、reset 清除本地主动停止意图，
以及恢复水位边界、恢复准备期间再次暂停、真实运行欠载不被屏蔽。

证据保存在 `test-results/2026-09-24-pause-resume/`。最终文件哈希见该目录的 `runtime-manifest.json`。
本次未做有声试听，也未在最终恢复缓冲改动后再次要求用户重复 B 站操作；
真机验证覆盖 USB 保持/恢复，后续自动测试覆盖恢复缓冲和 WASAPI 输出。长时间 PUBG 与目标 DAC 仍待验收。
