# 换机连接失败：USB 诊断与手动修复

## 适用情况

同一电脑换用另一台 iPhone/iPad 后无法连接，退出重开程序仍无效。`03-Check.cmd` 可以同时显示 READY：该脚本验证驱动文件、服务、父设备状态和 filter 登记，不执行 `usb_open`、序列号或活动配置读取，因此 READY 不代表采集通道一定可用。

当前没有取得用户故障发生时的完整日志，不能据此认定唯一根因。此改动提供具体诊断和局部恢复路径。

## 使用

1. 停止采集并关闭其他使用这台手机的程序，选择故障手机。
2. 点击主界面的“修复 USB”，接受 Windows 的管理员授权。主程序本身无需以管理员身份运行。
3. 等待提示。显示“USB 连接已恢复”后手动开始监听，现有静音和音量设置不变。

只有 Windows 仍能精确识别的 iPhone/iPad 父设备可以修复。Apple 服务暂时识别不到、但 Windows 仍能枚举的手机也保留在列表中，名称附加“USB 待检查”。刷新设备列表只读取信息。

取消 UAC、手机已拔出、其他桥接采集/修复会话占用设备、驱动绑定异常、重启失败和验证超时均会显示失败原因。Windows 返回要求重启系统时如实提示。一次点击只提交一次设备重启，不自动重复，不卸载或安装驱动，也不重启 Apple 服务。

## 实现与范围

- 连接前的探测将打开失败、序列号读取失败、设备身份无法匹配和活动配置读取失败分开报告。每个失败 I/O 立即保存返回值、Windows 错误码和 libusb 错误文本，避免下一次调用覆盖。
- 独立 `AudioBridge.UsbRepair.exe` 没有 libusb 导入。它通过 SetupAPI 的 `DIF_PROPERTYCHANGE / DICS_PROPCHANGE` 提交所选父设备的停止/重启请求，不依赖先打开故障的 USB 句柄。该方式遵循 [Windows 设备状态更改接口](https://learn.microsoft.com/en-us/windows/win32/api/setupapi/ns-setupapi-sp_propchange_params)。
- 提权后重新核对完整实例 ID、序列号、支持的 Apple 产品和 `usbccgp + libusb0` 绑定。禁止通配符、子接口、其他厂商和 Apple 音频配件；设备拔出或换成另一台时不改选目标。
- 采集和修复共用当前 Windows 会话内的逐设备互斥锁，保持旧版锁名称兼容。它不能协调不遵守该锁的第三方程序，因此操作前需关闭其他使用目标手机的软件。
- 助手返回成功后，还需连续两次观察到正常 PnP 子接口和同一台手机的 USBMux 记录，再实际打开 libusb、读取活动配置。命令执行成功本身不算连接恢复。
- 主程序等待助手最多 30 秒，随后正常枚举观察窗口为 15 秒。系统调用超时不会强杀正在执行设备重启的助手；助手返回前仍持有设备锁。

日志默认在 `%TEMP%\iOSAudioBridge-capture.log`；关注 `usb_probe`、`usb_repair`、`audio_session_error`。候选设备和目标使用指纹标识，避免直接写出设备序列号。

## 验证

原生回归覆盖 A/B 精确匹配、UDID 两种格式、拔出目标后拒绝改选、重复身份拒绝、非目标设备拒绝、同设备采集/修复互斥、另一台设备独立性，以及 PnP/USBMux 连续就绪条件。UI smoke 检查无设备时修复按钮不可用。

构建和离线测试结果单独记录。真实故障状态下的修复、UAC 交互及两台手机 A→B→A 的物理换机仍需实机验证；不把单元测试通过等同于该故障已根治。
