- Windows x64，本机既有 Apple USB 支持 / libusb0 filter 驱动。
- 用户的 iPhone 15 Pro Max，设备型号报告 `iPhone16,2`、系统报告 **iOS 26.6**。

  自包含运行时 .NET 8.0.28。

## 35 秒手机采集（含连接初始化，恢复另计）

命令：`AudioProbe --capture-muted 35 0 9`，返回码 **0**。

| 指标 | 实测 |
|---|---:|
| PCM | 48,000 Hz / 16 bit / Stereo |
| 音频包（含停止期间尾包） | 1,471 |
| 视频包 / 视频字节 | **0 / 0** |
| 已提交的有效 PCM 帧 | 1,504,416，约 31.34 秒 |
| 欠载事件 | **0** |
| 丢弃帧 | **0** |
| 稳定播放期间每秒采样的队列范围 | 800–1,952 帧，约 16.7–40.7 ms |
| WASAPI 周期 / 端点容量 | 480 / 1,056 帧，即 10 / 22 ms |
| 最后输入峰值 L / R | -2.806 / -2.851 dBFS |
| 最后输出峰值 L / R | -120 / -120 dBFS（静音表底） |
| USB 恢复 | `verified_normal`，helper exit=0；再次枚举可访问 |

本次与成功基线相同，停止时没有收到 RELS；协议等待结束后关闭流句柄，再由辅助程序
完成一次精确设备恢复。08:53:17.997 完成协议等待，08:53:29.513 确认普通 USB 配置，
加上此前约 6 秒收尾，停止总计约 **17.5 秒**。这不是播放音频的延迟。

证据位于 `test-results/2026-09-24/`，保留命令输出、USB 恢复日志与两个 WPF 检查 JSON。
`runtime-manifest.json` 记录最终本地包的关键文件哈希；真机测试后改动了 C ABI 错误文本边界
和 WPF 检查/绑定，没有更改该次验证的 USB / PCM / WASAPI 信号路径。

## 未完成的验收

- 用户要求此次静音，因此没有声学听感、左右定位或 pureaural + Sony H6 Air 验收。
- 没有 30 分钟 PUBG 或至少 2 小时测试，不能由 35 秒零欠载推断长期稳定。
- 没有拔线、输出设备移除、反复启停及播放暂停/恢复的真机回归。
- 没有实测端到端延迟、CPU/内存长期趋势或时钟漂移。上述队列范围和 WASAPI 周期不能当作端到端延迟。
- WPF 已完成隐藏窗口与绑定检查，未执行有人操作的完整窗口试听验收。
- ZL 压缩器、独占模式、自动连接和开机启动属于后续阶段。

建议下一次先使用目标 DAC 做可听见的左右声道/暂停恢复检查，再进行 30 分钟 PUBG 和
至少 2 小时统计；只有这些通过后再降低缓冲、接入压缩器。
